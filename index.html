01 — EF Core 10.0

LINQ and SQL Translation Improvements

Entity Framework Core 10.0 introduces powerful enhancements for LINQ queries, including native LeftJoin/RightJoin operators and improved parameterized collection translation.

LeftJoin & RightJoin Operators

Available

First-class LINQ support for LeftJoin and RightJoin methods. EF Core recognizes these methods and translates them to LEFT JOIN and RIGHT JOIN operations in SQL.

Old Way 
// Complex pattern
var query = context.Students
    .GroupJoin(context.Departments,
        student => student.DepartmentID,
        department => department.ID,
        (student, depts) => new {
            student, depts })
    .SelectMany(
        x => x.depts.DefaultIfEmpty(),
        (x, dept) => new {
            x.student.FirstName,
            Department = dept.Name ?? "[NONE]"
        });
EF Core 10 
// Clean syntax
var query = context.Students
    .LeftJoin(context.Departments,
        student => student.DepartmentID,
        department => department.ID,
        (student, dept) => new {
            student.FirstName,
            Department = dept.Name
                ?? "[NONE]"
        });

// RightJoin available too!

Parameterized Collection Translation

Available

New default translation strategy for parameterized collections. Each value becomes a scalar parameter with automatic padding for better query plan reuse.

EF 8.0 
// JSON array
int[] ids = [1, 2, 3];

var blogs = context.Blogs
    .Where(b => ids
        .Contains(b.Id))
    .ToListAsync();

-- SQL uses OPENJSON
WHERE [Id] IN (
  SELECT [value]
  FROM OPENJSON(@param)
)
EF Core 10 
// Scalar + padding
int[] ids = [1, 2, 3];

var blogs = context.Blogs
    .Where(b => ids
        .Contains(b.Id))
    .ToListAsync();

-- Individual params
WHERE [Id] IN (
  @ids1, @ids2, @ids3
)

-- 8 values pads to 10
WHERE [Id] IN (
  @ids1, ..., @ids8,
  @ids9, @ids10
)

02 — C# 14 Available Now

nameof with Unbound Generic Types

Use the nameof expression on unbound generic types without specifying type arguments. Useful for generic type introspection, logging, and code generation.

nameof with Unbound Generic Types

Available
Old Way 
// Required arguments
var name = nameof(List<int>);
// Returns: "List"

// Or Type.Name
var typeName = typeof(List<>).Name;
// Returns: "List`1"
C# 14 
// nameof on unbound
var listName = nameof(List<>);
// Returns: "List`1"

var dictName = nameof(Dictionary<,>);
// Returns: "Dictionary`2"

var funcName = nameof(Func<,,>);
// Returns: "Func`3"

03 — C# 14 Coming Soon

Upcoming C# 14 Features

The following C# 14 features are proposed but not yet implemented in .NET 10. These are expected to ship with .NET 11 / C# 14 final release.

field keyword
Access compiler-generated backing fields directly in custom property accessors
?.= operator
Null-conditional assignment operator for concise null handling
Lambda parameter modifiers
Use ref, in, out modifiers in lambdas without explicit parameter types
Custom ++, -- operators
User-defined increment and decrement operator behavior
Custom +=, -= operators
User-defined compound assignment operators for performance optimization
Extension blocks
Static extension methods and extension properties for types
Partial constructors/events
Partial instance constructors and events for better source generator support
Pipe Operator (|)
Chain functions in a linear pipeline using extension blocks and custom operator overloading
